# قرارات contaonline
الحالة: البنود التالية اعتمدها المالك في رده اللاحق للتدقيق، وتلغي المقترحات المخالفة في تقارير التدقيق القديمة.

| الموضوع | القرار المعتمد |
|---|---|
| المصدر | feat/approved-seller-app @ 1efb01fc1cd7bc62670510e57c6158734ad4bf05؛ نقل approved-runtime والضروري فقط |
| البنية | Node.js 24 LTS وFastify 5 وSQLite WAL على قرص محلي لسيرفر واحد، وملفات نسخ خاصة خارج public |
| الإصدار المثبت عند التنفيذ | Node 24.22.1؛ Fastify 5.12.7؛ package-lock.json، مع إعادة فحص تحديثات الأمان قبل إطلاق الإنتاج |
| بداية الاشتراك | أول تفعيل ناجح ذريًا أو تاريخ إداري صريح؛ لا إعادة بداية بالاستعادة أو المفتاح الجديد |
| التجديد | تمديد من نهاية الساري؛ يبدأ المنتهي من تاريخ اعتماد الإدارة؛ audit ومشرف وسبب ومرجع دفع |
| الأوفلاين | قد يصل لنهاية الاشتراك، سياسة قابلة للضبط لكل باقة؛ لا حظر فوري للأوفلاين ولا حماية مطلقة من تعديل العميل/الساعة |
| مفاتيح لاحقة | يمكن اعتمادها آليًا إذا كان الدخول صحيحًا والاشتراك صالحًا ولا نشاط متعارض؛ لا مراجعة إدارية افتراضية لكل مفتاح |
| النشاط | وجود مفتاحين أو عودة القديم أو عدة تبويبات أو رفع سجل قديم لا تكفي للمخالفة؛ المطلوب تداخل نشاط متصل فعلي |
| سلطة الرفع | منفصلة عن اعتماد الترخيص والنشاط؛ الجديد المعتمد يحصل جيل كتابة/رفع جديد؛ القديم لا يدمج تغييرات تلقائيًا |
| الانتهاء | عرض محلي وتصدير بعد مصادقة محلية؛ منع البيع/التعديل/الاستيراد، دون حذف أو منح نسخ سحابي |
| النسخ | اختيارية ومغلقة دون اشتراك وموافقة؛ انتهاء خدمتها منفصل عن انتهاء ترخيص التطبيق |
| الاحتفاظ | 30 يومًا بعد انتهاء خدمة النسخ؛ تنزيل مأذون وتنبيه داخل الحساب قبل حذف بمهمة مدققة ومختبرة؛ المحلي محفوظ |
| المستودع | يظل عامًا؛ نوصي بالخاص، ولا تغيير visibility دون موافقة منفصلة |
| الإذن | تنفيذ على دفعات في الوجهة، دفع فروع ومتابعة CI؛ لا نشر أو تغيير سيرفرات أو DNS/Nginx |

## قواعد تنفيذية قابلة للضبط قبل وحدة النشاط
الافتراض التنفيذي المعروض للتنفيذ: heartbeat كل 60 ثانية أثناء الواجهة فقط، lease خمس دقائق، ومهلة تداخل خمس دقائق إضافية مع ملاحظات متكررة من تثبيتين؛ لا حظر بسبب نبضة واحدة/انقطاع.
حد التفعيلات الجديدة المبدئي: 3 طلبات ناجحة للحساب خلال 24 ساعة، مع 429 ومهلة معلنة عند التجاوز؛ لا تمديد اشتراك ولا حظر دائم. ستغطيه اختبارات الحدود والسباقات، ويمكن ضبطه.
قبول بديل آلي لا يتقاعد منه القديم نهائيًا؛ يصير غير مخول للرفع مع بقاء ربطه وترخيصه وسجل نشاطه. راجع آلة الحالات في INSTALLATION_POLICY قبل تنفيذها.
هذا يثبت علاقة مفاتيح وبرنامج عميل متعاون؛ لا يثبت هوية العتاد بعد مسح التخزين.

## حدود الاستقلال
لا إعادة استخدام لمفاتيح إصدار تراخيص Android الخاصة، ولا تعديل لتفعيله أو ملفات المصدر أو workflows.
مفاتيح إصدار تصريح الويب ستكون جديدة خاصة بالخدمة، خارج Git وpublic؛ فقط مفاتيح تحقق عامة في العميل.
مراجع الدعم: https://nodejs.org/en/about/previous-releases ، https://fastify.dev/docs/latest/Reference/LTS/ ، https://www.sqlite.org/wal.html

## حالة التنفيذ الحالية
القرارات المعتمدة نُفذت في دفعات المراجعة، مع بقاء بوابة قبول الإنتاج. القيم التنفيذية المعلنة قابلة للضبط. النزاع المسجل pending-conflict يبقى للمراجعة الإدارية حتى بعد انتهاء lease؛ المفتاح الجديد الذي لم يسجل عليه نزاع يُقبل آليًا عند غياب النشاط الحديث. بداية المدة وتجديدها واستحقاق النسخ لا تتغير بهذا الانتقال.
النسخ الافتراضي مغلق، ويختار المستخدم يوميًا أو أسبوعيًا أو كل دقيقة أثناء الفتح بعد موافقة مستقلة. الحدود الفنية الأولية والحفظ/الحذف موثقة في BACKUP_REVIEW وOPERATIONS. لا SaaS أو نشر أو تغيير visibility.
