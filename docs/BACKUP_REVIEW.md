# Optional cloud backup review

This is a separate paid entitlement and explicit consent, disabled by default. An application license never activates backup uploads. Local state/users, service identity and app resources remain separate. No service tokens, installation private keys or issuing keys belong to the snapshot contract.

Browser storage upgrades the shop database to IndexedDB v2 without replacing v1 data. Each business snapshot change and its stable-ID ordered outbox delta share one transaction. User changes are also queued atomically. Consent creates the first snapshot; subsequent keyed-collection deltas preserve edits, deletes and order. Import/restore disables sending until an explicit new-stream review. Safety state and local users are retained before replacement, and restored users must authenticate locally.

Daily/weekly/foreground-minute scheduling is configurable; foreground/network/start hooks respect that cadence, with manual Sync now and bounded backoff. There is no promise of iOS background execution. Rows leave the outbox only after a durable cursor acknowledgement; a lost ACK can be retried idempotently. Opening a replacement stream requires confirming the current latest server version. Different writer generations never merge automatically.

Server receives bounded batches over same-origin session/CSRF plus a one-use installation-key proof bound to operation and payload digest. Content download also requires the currently approved installation proof, scoped account and separate backup/grace entitlement. Support metadata privileges do not include content. Files are private and versioned, checksummed and fsynced before a SQLite FULL/WAL commit and ACK. Server materializes a version after each batch; wire changes remain deltas. Initial technical limits: 50 events/batch, 10 MiB HTTP request, 8 MiB materialized snapshot, 256 MiB/account private versions. Quota pauses uploads with an error and preserves local data; it does not silently delete active versions. Space/retention operations need measured refinement before larger deployments.

App expiry and backup expiry are checked independently: no new accounting writes after app expiry, but a separately entitled current writer may finish pending backup uploads. Expired backup service stops uploads; authenticated, installation-authorized download remains for 30 days. The account panel shows expiry and deletion date. The scheduled retention command queues a notice first, waits at least a day after the notice and the full 30-day grace, rechecks entitlement under the SQLite lock, and audits deletion. Dry run never deletes or queues notices. Account/license state changes do not run deletion and never touch browser data.

Local tests added: snapshot/delta reconstruction, immutable inputs, consent/entitlement, lost-ACK idempotency, bad delta rollback, isolation, support denial, old writer denial, independent expiry/grace, checksums, replacement confirmation, dry-run/audited retention. Real browser test adds opt-in, offline delta and clean-browser restore; its CI result must be recorded after execution. These tests do not constitute physical iPhone acceptance or operational capacity measurement.
