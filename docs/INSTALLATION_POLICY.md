# سياسة التثبيتات — آلة الحالات قبل التنفيذ
الحالة: تصميم مختصر معروض قبل تنفيذ وحدة المرحلة الرابعة؛ ليس سلوكًا منفذًا في المرحلة الأولى.

## محاور مستقلة
| المحور | الحالات |
|---|---|
| الترخيص | awaiting-first-activation / active / expired / blocked |
| اعتماد التثبيت | pending-conflict / approved / rejected / suspended / revoked |
| النشاط المتصل | absent / lease-live / overlap-observed / overlap-confirmed |
| سلطة الرفع | none / current-writer(generation) / superseded-writer |

approved لا يعني نشاطًا حاضرًا، ولا يمنح الرفع دون current-writer. superseded-writer ليس رفضًا نهائيًا لترخيص القديم أو محوًا له.

## الانتقالات
| الحدث الموثق | النتيجة |
|---|---|
| تسجيل صحيح + اشتراك متاح + أول مفتاح ناجح | اعتماد ذري، بدء مرة واحدة، وتخصيص سلطة الكاتب |
| مفتاح لاحق + اشتراك صالح + غياب نشاط حديث متعارض | اعتماد آلي ضمن rate limits، بنفس نهاية الاشتراك، جيل رفع جديد، والقديم يبقى مسجلًا دون سلطة دمج |
| مفتاح لاحق + نشاط حديث للتثبيت السابق | pending-conflict وتحذير وaudit ومراجعة إدارية؛ لا تصريح كتابة/بيانات محل للطلب غير المأذون |
| عودة القديم بمفتاحه المعروف | يقبل إثبات حضوره في قناة observation حتى لو لم يملك الرفع؛ لا مخالفة بمجرد العودة ولا استعادة سلطة الدمج |
| تبويبان بنفس installation/key | lease واحد وتسلسل منسق محليًا؛ ليسا جهازين |
| نشاط موثق متكرر من مفتاحين داخل نافذة تداخل مع استمرار كليهما بعد المهلة | overlap-confirmed وحادث قابل للمراجعة/تعليق مضبوط، دون حذف بيانات أو حظر نهائي تلقائي |
| نوم/خلفية/فقد شبكة/نبضة واحدة أو رفع أحداث قديمة | انتهاء lease أو تحديث cursor حسب الحالة؛ لا incident تزامن بذاته |
| قرار مشرف بالسماح/رفض/تعليق/فك/حظر | انتقال مصرح مع سبب ومشرف ومرجع/وقت وaudit؛ لا محو سجل قديم |
| تثبيت غير الكاتب يرفع أحداثًا | رفض الدمج؛ بياناته للاسترداد/تصدير مأذون منفصل، لا overwrite للكاتب الحالي |

## القيم التنفيذية المقترحة
Heartbeat عند الواجهة المرئية كل 60 ثانية، lease 300 ثانية، مهلة تداخل إضافية 300 ثانية. الحد المبدئي 3 تفعيلات ناجحة للحساب في 24 ساعة. كلها قابلة للضبط، ولا تُستخدم لتغيير فترة الترخيص.
تصحيح الساعة بمرجع السيرفر دفاعي؛ timestamp معاملات العميل ليس برهان تزامن.
يجب إثبات المفتاح لكل قناة حساسة، مع nonce وغرض/جلسة/حساب وتسلسل ومكافحة replay، دون منح بيانات المحل عبر قناة presence.
لا يُنشأ staging عام عند تنفيذ الاختبارات.

## الاختبارات الملزمة قبل الدمج
1. أول تفعيلين باتصالين SQLite متنافسين: فترة واحدة وحد كاتب واحد.
2. إعادة تثبيت عند غياب القديم: قبول آلي، بقاء نهاية الاشتراك والسجل السابق.
3. جديد مع lease حديث: تعليق الطلب، دون تمديد أو بيانات أو grant.
4. القديم يعود وحده بعد اختفاء الجديد: لا اشتباه آلي ولا استعادة upload authority.
5. القديم والجديد يستمران متصلين بعد المهلة: incident قابل للمراجعة؛ عدة تبويبات للمفتاح نفسه لا تنشئه.
6. خلفية/resume وشبكة متذبذبة وتأخر/replay الرسائل: لا حظر كاذب؛ nonce المكرر مرفوض.
7. رفع معاملات قديمة: outbox/cursor لا يُستخدم كإثبات نشاط متزامن.
8. rate limit واشتراك منته ودخول خاطئ ومفتاح غير مأذون: لا تصريح أو تمديد أو كشف محل.
9. محاولات منح/رفع متنافسة: generation واحد ومصادقة نطاق؛ القديم لا يدمج فوق الحالي.
10. كل إجراءات الإدارة مخولة وبسبب وaudit؛ دعم metadata لا يحمل نسخ العملاء.
11. الاستعادة لا تعيد بداية المدة ولا تستورد مفاتيح/جلسات خدمة من النسخة.
12. قناة presence للقديم المعروف تبقى قابلة للرصد بعد الاستبدال الآلي؛ الحظر الإداري الصريح يظل منفصلًا.
