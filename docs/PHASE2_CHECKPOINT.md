## طبيعة هذا الفرع
feat/phase-2-pwa يحتوي الآن نقطة استلام وثائقية فوق المرحلة الأولى. كود المرحلة الثانية الموجود على الجهاز لم يُنقل إلى GitHub قبل فقد بيئة التنفيذ.
نجاح CI لهذه النقطة يعني نجاح كود المرحلة الأولى؛ لا يعتبر إثباتًا لكود PWA غير المدفوع.
المصدر وأندرويد وتفعيله ومفاتيحه وworkflows لم تتغير.

## العمل المحلي المنفذ قبل الانقطاع
نسخة الوجهة: work/contaonline داخل مساحة المهمة الأصلية على Windows، على فرع محلي feat/phase-2-pwa.
يوجد عمل غير ملتزم/غير مدفوع؛ لا تستبدل الشجرة أو تعمل reset --hard عند استعادة الاتصال.

ملفات أضيفت محليًا:
- shared/permit.mjs: عقد تصريح ويب ECDSA P-256 مشترك، canonical serialization، ربط الحساب/المحل/التثبيت وبصمة المفتاح والتحقق من الانتهاء.
- web/service-store.js: IndexedDB مستقل للخدمة، CryptoKey غير قابل للاستخراج، اختيار مفتاح واحد عند سباق التبويبات، وتصريح لكل نطاق حساب.
- web/bootstrap.js: شاشة خدمة قبل تشغيل المصدر، عقد طلب تفعيل مستقبلي، نطاق محل ثابت وفتح محلي للعرض بعد الانتهاء، وحماية الكتابة/تراجع الساعة.
- web/web-database.js: بوابة حفظ/استعادة/مستخدمي المحل، وقاعدة منفصلة لكل حساب/محل.
- web/web-export.js: Blob/File وتنزيل ومشاركة محلية دون /api/export؛ لا ادعاء أن اختيار التنزيل يثبت الحفظ النهائي.
- web/web-report-pdf.js: jsPDF ونصوص وخطوط عربية مضمّنة بدل تصوير الجداول؛ لم يفحص الناتج بصريًا أو باستخراج النص بعد.
- web/pwa.js وweb/sw-template.js: تحقق بايتات الموارد عند install، cache لكل إصدار، update waiting وموافقة سلامة من النوافذ وحفظ المسودة، وعدم كاش API أو بيانات أعمال.
- web/landing.html وlanding.js وlanding.css وweb.css: اختيار أندرويد/آيفون قابل للتغيير، رابط APK معطل دون إعداد، إرشاد Safari، لغتان وحدود التخزين.
- server/app.mjs وserver/start.mjs: Fastify gate إجباري عالي العشوائية لكل routes/assets/API/health، فحص بصمات البناء، loopback، ورفض تشغيل إنتاجي لهذه المرحلة.
- scripts/staging-key.mjs: ملف وصول خاص خارج public/Git، بلا طباعة السر.
- scripts/adapt-web.mjs: تحويلات fail-closed في المخرجات فقط؛ approved-runtime يبقى مطابقًا للبصمات.
- scripts/build.mjs: بناء Phase 2 مع أيقونات من الشعار وmanifest وjsPDF ومخرجات مغلقة خلف staging.
- tests/permit.test.mjs وtests/staging.test.mjs، وتحديث package.json/lockfile/tsconfig والحزمة.

التبعيات المحلية الجديدة المثبتة:
jspdf 4.2.1، @fastify/cookie 11.1.3، @playwright/test 1.64.1، sharp 0.35.5.
Node المستخدم 24.22.1 وnpm 11.19.1. الموارد الحالية من npm لا تُسحب وقت استعمال التطبيق.

## ما نجح فعليًا محليًا في المرحلة الثانية
آخر npm run check اكتمل exit 0، ويشمل:
1. تطابق 52 بصمة مصدر.
2. تجهيز sql.js المحلي ببصمته.
3. lint للكود الجديد وtypecheck للسكربتات والخادم والعقد المشترك واختبارات الوحدة.
4. baseline المصدر الستة.
5. build: phase=2، files=62، precacheEntries=58، version=8a0eb252684bd41817fa، deployable=false.
6. اختبارات الوحدة/التكامل الخمسة: تصريح صالح وربط/عبث/انتهاء، رفض مفتاح خاص/صلاحية غريبة، بصمات المصدر، فشل مورد/مصدر معدل، ورفض staging غير المأذون على جميع المسارات المحددة.
7. npm audit بعد تثبيت التبعيات الجديدة أظهر صفر ثغرات معروفة.

هذه النتائج لا تثبت تشغيل المتصفح أو جودة PDF أو تحديثًا آمنًا فعليًا مع مسودة.

## موضع الانقطاع الدقيق
- اكتمل تنزيل Chromium وWebKit للاختبارات الآلية.
- محاولة smoke probe من Node REPL لم تستطع استيراد Fastify عبر loader الخاص به؛ لا تعالج ذلك بتغيير Fastify لأن npm test عبر Node الحقيقي نجح.
- بدأ إعداد playwright.config.mjs وtests/e2e/app.spec.mjs واختبارهما عبر native Node CLI، لكن البيئة أصبحت unavailable قبل عودة نتيجة الاستدعاء.
- لا يمكن التأكيد أن آخر ملفي E2E حُفظا أو أن العملية بدأت. يجب التحقق منهما على القرص عند الاستئناف.
- ما زال اختبار المنتج التشخيصي يطبع أسماء حقول نموذج المنتج؛ استبدله بسيناريو بيع ومخزون فعلي قبل اعتماد CI.
- لم يولد/يفحص PDF فعليًا، ولم ينجح أي E2E أو WebKit/iPhone بحسب النتائج المتاحة.
- لم يُنفذ backend الحسابات/MFA/SQLite migrations أو وحدة النشاط أو النسخ السحابي أو الحذف.

## الاستئناف دون طلب موافقة السياسات مرة أخرى
1. استعد بيئة الجهاز ثم افحص git status والملفات المحلية قبل أي fetch/merge. احفظ التغييرات غير المدفوعة دون فقد.
2. اقرأ DECISIONS وINSTALLATION_POLICY؛ المالك وافق على الاستمرار المرحلي بعد نجاح المرحلة الأولى.
3. أكمل Playwright على native Node 24، لا loader الـREPL: بوابة غير مفعل، مفتاح غير قابل للاستخراج، إنشاء مستخدم محلي، بيع ومخزون ودين، أوفلاين وإعادة فتح، quota/transaction، تحديث مع مسودة وفشل precache.
4. تحقق من PDF عربي وفرنسي: نص قابل للبحث ومخرجات بصرية سليمة، وحفظ JSON/XLSX/PDF محليًا وفحص الشبكة.
5. حدّث CI للـE2E، وادفع دفعة المرحلة الثانية فقط بعد توثيق النتائج والفجوات، ثم تابع المراحل 3–6.
6. لا تنشر ولا تغير VPS/DNS/Nginx أو visibility؛ لا تمس المصدر أو Android. توصي الوثائق بخصوصية المستودع دون تغييرها.
