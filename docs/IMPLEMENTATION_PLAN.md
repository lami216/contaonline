# المراحل ومعايير القبول
كل مرحلة commit نظيف ونتائج فعلية وhandoff؛ لا نقل ملفات = اكتمال المنتج.

| المرحلة | العمل | بوابة النجاح |
|---|---|---|
| 1 | نقل allowlist، 52 بصمة، خطوط ورخصة وSQL مثبت، حزمة/lockfile/CI ووثائق | baseline الستة + lint/types + فشل البصمة/المورد المفقود + build 45 موردًا + CI ناجح على الفرع |
| 2 | PWA وتخزين وتحديث وتصدير محلي نصي وكاميرا/fallback | موارد كاملة، متصفحات فعلية أوفلاين/تحديث/فشل quota، لا رفع بيانات، JSON/XLSX/PDF نص عربي، staging مقفل |
| 3 | SQLite migrations، حسابات وجلسات وbootstrap/MFA وإدارة وتفعيل موقّع | تفعيل/تجديد/انتهاء/عبث/nonce/ساعة؛ سباق حقيقي؛ فتح محلي لا تكسره session الخدمة؛ API محمي |
| 4 | آلة التثبيتات المعروضة، leases ومراجعة الإدارة وسلطة الرفع | الاختبارات الـ12 في INSTALLATION_POLICY؛ لا حظر كاذب أو دمج قديم |
| 5 | نسخ اختياري وطابور ذري وsnapshots/deltas واسترداد واحتفاظ | عزل A/B؛ retry بعد commit؛ نسخة فاسدة؛ استعادة تثبيت نظيف؛ موافقة منفصلة وحذف بعد 30 يومًا مدقق |
| 6 | تقوية وتشغيل معزول وقبول iPhone وخطط نشر/استعادة | اختبارات مراجعة وحمل مقاس وتعافٍ؛ قبول هاتف فعلي؛ نشر فقط بإذن منفصل |

المشاهدة على جهاز ثانٍ تجهيز معماري فقط؛ تعدد الكتابة خارج الإصدار الأول.
لا أرقام سعة مختلقة أو ادعاء iPhone من Chromium. لا نشر في المرحلة الأولى، وCI بلا Actions من المصدر أو صلاحيات نشر.

## حالة الدفعات
المراحل 1–5 لها فروع وcommits وCI ناجح مسجلة في HANDOFF وTEST_REPORT. المرحلة السادسة تنفيذ وتقوية وقبول قيد المراجعة، وليست إطلاقًا إنتاجيًا. أضيفت سباقات باتصالين، تعافي مشفر، مراجعة PDF بصرية، بحث إداري مقسّم، وقنوات مفتاح مستقلة عن جلسة الخدمة. تحقق المتصفحين يسجل بحسب نتيجة الـcommit الفعلية.

الخطوة التالية عند تسليم الفحص الآلي: تنفيذ قائمة IPHONE_ACCEPTANCE على جهاز حقيقي بعد اعتماد هدف staging مقفل، وتوسيع قبول UI المحاسبي واختبارات الأعطال التشغيلية في RELEASE_ACCEPTANCE. لا يتضمن هذا تكليفًا بالنشر أو إذنًا بتعديل VPS/DNS/Nginx.
